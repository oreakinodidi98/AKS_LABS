## Context

The aim is to package the application in a Docker image so it can run in a
container and later be deployed to AKS.

```text
Application source + Dockerfile
              │
              ▼
         Docker image
          ┌───┴────┐
          ▼        ▼
   Local container  Docker Hub
                         │
                         ▼
                        AKS
```

The Dockerfile contains the instructions to build the application and run it
inside a container. You can ask Copilot to explain individual instructions as
you work through the file.

## Dockerfile

This Dockerfile has two stages: the SDK image builds and publishes the
application, then the smaller ASP.NET runtime image runs it.

```dockerfile
FROM --platform=$BUILDPLATFORM mcr.microsoft.com/dotnet/sdk:8.0 AS build
WORKDIR /src
COPY CaldovaBakery.csproj ./
ARG NUGET_SOURCE=https://api.nuget.org/v3/index.json
RUN dotnet restore CaldovaBakery.csproj --source "$NUGET_SOURCE"
COPY . .
RUN dotnet publish CaldovaBakery.csproj -c Release -o /app/publish --no-restore

FROM mcr.microsoft.com/dotnet/aspnet:8.0 AS runtime
WORKDIR /app
LABEL com.azure.containerizationassist.createdby="containerization-assist"
RUN useradd --create-home --uid 10001 bakery
COPY --from=build --chown=bakery:bakery /app/publish .
ENV ASPNETCORE_URLS=http://+:8080
EXPOSE 8080
USER bakery
HEALTHCHECK --interval=30s --timeout=5s --start-period=60s --retries=3 \
  CMD ["bash", "-c", \
    "exec 3<>/dev/tcp/127.0.0.1/8080 && \
    printf 'GET /health HTTP/1.1\r\nHost: localhost\r\nConnection: close\r\n\r\n' >&3 && \
    head -n 1 <&3 | grep -q '200 OK'"]
ENTRYPOINT ["dotnet", "CaldovaBakery.dll"]
```

The build stage uses `$BUILDPLATFORM` to run the .NET SDK on the builder's
native CPU. The published DLL is portable, so the runtime image can target
`linux/amd64` when building on an ARM64 machine.

| Instruction | What it does |
| --- | --- |
| `FROM` | Selects the base image for each stage. |
| `WORKDIR` | Sets the working directory inside the image. |
| `COPY` | Copies files into an image or between stages. |
| `ARG` | Defines a value that can be supplied during the build. |
| `RUN` | Runs a command while building the image. |
| `EXPOSE` | Documents the port used by the application. |
| `USER` | Sets the user used to run the application. |
| `HEALTHCHECK` | Checks whether the application is responding. |
| `ENTRYPOINT` | Sets the command that starts the application. |

## Build the image

Open a PowerShell terminal in the application folder:

```powershell
cd AKS_Workshop\assets\module3
docker build --platform linux/amd64 -t caldova-bakery:v1 .
```

The `-t` option names and tags the image. The `.` uses the current directory's
Dockerfile and application files. This command builds an image; running it
creates a container.

### If package restore fails with NU1301

`dotnet restore` downloads the app's packages. A container does not inherit your
Windows NuGet configuration. If Windows restore works but Docker cannot reach
`https://api.nuget.org/v3/index.json`, compare the Windows package sources:

```powershell
dotnet nuget list source
```

For the lab environment configured with the `azure-default` mirror, build from
the application folder with:

```powershell
docker build --platform linux/amd64 `
  --build-arg "NUGET_SOURCE=https://packagefeedproxy.microsoft.io/nuget/v3/index.json" `
  -t caldova-bakery:v1 .
```

The mirror was verified in this lab; other environments should use their own
approved feed. NuGet.org remains the Dockerfile default. Do not put passwords
or tokens in build arguments or disable TLS certificate validation. If no
approved feed is reachable, check Docker Desktop's proxy/VPN settings and
organization-approved certificate configuration.

## Run the container

For a standalone container using SQLite, run this in PowerShell:

```powershell
docker run --rm -it --platform linux/amd64 `
  -p 127.0.0.1:8080:8080 `
  -v caldova-bakery-data:/home/bakery `
  -e "ConnectionStrings__SqliteDatabase=Data Source=/home/bakery/caldova-bakery.db" `
  caldova-bakery:v1
```

Open **http://localhost:8080** once startup completes.

- The port mapping makes the app available on your PC at port `8080`.
- The named volume preserves the SQLite database after the container stops.
- The database path uses a directory writable by the non-root container user.

Press **Ctrl+C** to stop. For the SQL Server version, use
[Docker Compose](assets/module3/compose.yaml), which starts both the app and
database.

## Publish the image to Docker Hub

Sign in to Docker Hub, tag the local image with your Docker Hub username, then
push it to the registry:

```powershell
docker login
docker tag caldova-bakery:v1 YOUR_DOCKERHUB_USERNAME/caldova-bakery:v1
docker push YOUR_DOCKERHUB_USERNAME/caldova-bakery:v1
```

Replace `YOUR_DOCKERHUB_USERNAME` with your Docker Hub username. The tagged
image can then be pulled by Kubernetes using
`YOUR_DOCKERHUB_USERNAME/caldova-bakery:v1`.
