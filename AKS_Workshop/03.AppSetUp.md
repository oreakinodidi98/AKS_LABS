## Context

The storefront includes Home, Our Bakes, product details, Our Story, Contact and
Find Us pages. Visitors can search products, add pastries to a basket, change
quantities and place a fictional pickup order. Admins can add, view, edit and
delete products at `/Admin`. Products contain an ID primary key, name, price,
image, description and category. Products and orders persist in SQL Server.

> **Demo only:** ASP.NET Core 3.0 is intentionally outdated and unsupported.
> There is no authentication. Everyone with access can modify products. Keep the
> app local and isolated. Do not enter real customer information. No payments,
> email confirmations, deliveries or real pickup orders are processed.

## Start the demo

Install Docker Desktop with Linux containers and Docker Compose v2. The demo
requires x86-64 Linux containers; ARM hosts need working emulation.

```powershell
cd AKS_Workshop/assets/module3
```

Set `BAKERY_SQL_PASSWORD` privately in your terminal, or provide it in a local
`.env` using [.env.example](assets/module3/.env.example). Use a strong disposable
password, never a real credential. See the [app setup instructions](assets/module3/README.md)
for password requirements, runtime prerequisites and local SQL Server options.

```powershell
docker compose up --build -d --wait --wait-timeout 240
```

Open **http://localhost:5080** for the store or **http://localhost:5080/Admin** for
product management. Set `BAKERY_PORT` before startup if port 5080 is busy.
The initial startup creates the database and seeds six sample bakery products.

## Demo flow

1. Browse Our Bakes and try a search or category filter.
2. Open a product, choose a quantity and add it to the basket.
3. Update or remove a basket item, then proceed to checkout.
4. Enter fictional details and place a demo order. Review the saved summary.
5. Open Manage Products in the footer and create, edit and delete a product.
6. Open Last Order to show that previous orders retain their product snapshots.

## Validation and cleanup

With the app running, use PowerShell 7 from the module 3 directory:

```powershell
./tests/SmokeTest.ps1 -BaseUrl http://localhost:5080
docker compose down
```

The smoke test checks CRUD, validation, basket totals, checkout and receipt
isolation. It leaves one fictional order in SQL Server. Stopping Compose keeps
the SQL data. Only use `docker compose down --volumes` when you intend to erase
all demo data. See the [application README](assets/module3/README.md) for known
limitations, troubleshooting and non-Docker setup.
