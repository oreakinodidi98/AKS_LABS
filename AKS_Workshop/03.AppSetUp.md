# App Setup

Module 3 uses **Caldova Bakery**, an ASP.NET Core 8.0 MVC application backed by
SQLite for local runs. The source is in [assets/module3](assets/module3).
SQL Server remains available for the later Docker/AKS modules.

## Context

The storefront includes Home, Our Bakes, product details, Our Story, Contact and
Find Us pages. Visitors can search products, add pastries to a basket, change
quantities and place a fictional pickup order. Admins can add, view, edit and
delete products at `/Admin`. Products contain an ID primary key, name, price,
image, description and category. Products and orders persist in a local database
file, so they remain available after the app stops.

> **Demo only:** .NET 8 reached end of support on November 10, 2026.
> There is no authentication. Everyone with access can modify products. Keep the
> app local and isolated. Do not enter real customer information. No payments,
> email confirmations, deliveries or real pickup orders are processed.

## Start the demo

Run the app directly on your machine for this module. Building and running a
Docker container is covered in the next module.

### Prerequisites

- The [.NET 8 SDK](https://dotnet.microsoft.com/download/dotnet/8.0), which includes
	the ASP.NET Core 8 runtime. Choose **Arm64** on Windows ARM or **x64** on an
	Intel/AMD machine. A .NET 10 SDK can build the app, but its runtime alone cannot
	run it; install the ASP.NET Core 8 runtime as well if retaining that SDK.
- An internet connection for the first package restore and write access to the
	app directory. No SQL Server, LocalDB, Docker, database account or password is
	required for this module. SQLite is included with the app and works on ARM64.

### Configure the database

There is nothing to install or configure for the database. The app creates
`caldova-bakery.db` in its directory on first startup and adds six sample products.
Think of this file as the bakery's saved data. You do not need to open or edit it.

From the repository root, open PowerShell and change to the app directory.
**Skip the `cd` command if your terminal is already in this directory.**

```powershell
cd AKS_Workshop/assets/module3
dotnet --list-sdks
dotnet --list-runtimes
```

Confirm that the runtime list includes `Microsoft.AspNetCore.App 8.0.x` and
`Microsoft.NETCore.App 8.0.x` before continuing.

If you previously set `ConnectionStrings__BakeryDatabase` for LocalDB, that value
is ignored while the default SQLite provider is selected. If you explicitly set
`DatabaseProvider` to `SqlServer`, remove that override before running locally:

```powershell
Remove-Item Env:DatabaseProvider -ErrorAction SilentlyContinue
```

SQL Server is optional. Its separate setup is in the
[application README](assets/module3/README.md#optional-sql-server).

### Build and run

Run these commands from the app directory in the same terminal:

```powershell
dotnet restore
dotnet run --urls http://localhost:5080
```

Open **http://localhost:5080** for the store or **http://localhost:5080/Admin** for
product management. Keep the terminal running while you use the app. If port
5080 is busy, choose another port in `--urls` and use that port in your browser
and smoke-test command.

`dotnet run` builds and starts the app. Wait for `Now listening on:
http://localhost:5080` before opening the browser. If startup fails, check that
the required 8.0 runtimes are installed and that the app directory is writable.

## Demo flow

1. Browse Our Bakes and try a search or category filter.
2. Open a product, choose a quantity and add it to the basket.
3. Update or remove a basket item, then proceed to checkout.
4. Enter fictional details and place a demo order. Review the saved summary.
5. Open Manage Products in the footer and create, edit and delete a product.
6. Open Last Order to show that previous orders retain their product snapshots.

## Validation and cleanup

Leave the app running and open a second PowerShell 7 terminal in the module 3
directory to run the smoke test:

```powershell
./tests/SmokeTest.ps1 -BaseUrl http://localhost:5080
```

The smoke test checks CRUD, validation, basket totals, checkout and receipt
isolation. It leaves one fictional order in the local SQLite database.

Press `Ctrl+C` in the app terminal to stop the server. Products and orders stay
in `caldova-bakery.db`, but the in-memory basket and Last Order session are lost
when the app restarts. Files ending in `-wal` or `-shm` are SQLite working files;
leave them alone while the app is running. These files are excluded from Git.

There is no need to delete the database between runs. To intentionally reset
the local demo, **stop the app first**, then run this from its directory:

```powershell
Remove-Item ./caldova-bakery.db, ./caldova-bakery.db-wal, ./caldova-bakery.db-shm, ./caldova-bakery.db-journal -ErrorAction SilentlyContinue
```

This permanently deletes local products and orders. The next startup recreates
the database with sample products. Switching to SQL Server later uses a separate
database; it does not transfer or erase your SQLite data.
See the [application README](assets/module3/README.md) for known limitations.
